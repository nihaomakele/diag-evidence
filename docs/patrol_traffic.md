# 多机器人迎面冲突让行

两个机器人同时尝试进入对方所在的格子时，交通规则会禁止交换位置。旧方式让两个机器人分别重算路线。在种子 42 和 48 的报告延迟场景里，两台机器人绕到相邻路口后再次相遇，循环持续到任务逾期。

`--traffic yield` 在迎面冲突已有等待记录时尝试单方绕行。执行任务的机器人优先于回驻点的机器人。两台都在执行任务时，先比较截止时间，再比较任务优先级，最后按机器人编号决胜。优先尝试让低优先一方绕行，必要时交换让行角色。路线要避开当前占用格，并留够剩余服务和返回驻点所需的能量。找到可行路线后，只替换绕行一方的路线。当前找不到可行绕路时，两方保持等待并按周期重试。

```bash
diag-evidence patrol-demo --scenario delayed --seed 42 --execution confirmed --output-dir artifacts/legacy-traffic
diag-evidence patrol-demo --scenario delayed --seed 42 --execution confirmed --traffic yield --output-dir artifacts/yield-traffic
python scripts/patrol_traffic_compare.py --output-dir artifacts/traffic-study
```

回放中的“下一条异常”可跳到绕行事件。种子 42 和 48 之前都按时完成 6/8 项，开启后都完成 8/8 项。两例的交通等待分别从 105 步降到 6 步、从 112 步降到 5 步。动态重规划分别从 52 次、56 次降到 1 次。

对照固定执行确认、核验策略和匹配分配器。每个布局分别运行原交通规则和单方绕行。布局种子 40–59 是前一轮已见数据，60–79 是本轮新布局。五类场景共 200 组配对、400 次仿真。下表列出新布局的平均结果。

| 场景 | 按时完成率 | 交通等待步数 | 能耗 |
|---|---:|---:|---:|
| 正常通信 | 100% → 100% | 6.45 → 3.60 | 141.35 → 141.60 |
| 回执延迟 12 步 | 100% → 100% | 6.45 → 3.60 | 141.35 → 141.60 |
| 主动回执丢失 | 100% → 100% | 6.45 → 3.60 | 141.35 → 141.60 |
| 机器人临时故障 | 98.125% → 100% | 16.95 → 3.35 | 146.60 → 147.90 |
| 回执延迟 32 步 | 100% → 100% | 9.65 → 7.10 | 251.00 → 250.35 |

这项规则处理两个相向机器人已有可行替代路线的情况。单通道无法绕行时仍会等待。能耗会随改道距离变化，长延迟下的执行确认仍可能触发重派。实验继续使用二维栅格和现有交通碰撞检查。[机器可读结果](results/patrol_traffic_20261110.json)
