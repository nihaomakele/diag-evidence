# 真实数据基线：方法、结果与边界

这是0.2.0.dev0的可复现实验，不是可以部署的诊断模型，也没有证明新的诊断算法优于既有方法。它回答两个不同的问题：真实信号上的分类器是否有效；相同工具输出下，参考适用性规则是否按要求限制结论。

## 数据与许可

使用Hoang Si Hong、Nguyen Thuan在Mendeley Data发布的[HUST bearing v3](https://data.mendeley.com/datasets/cbv7jyx4p9/3)，DOI `10.17632/cbv7jyx4p9.3`，CC BY 4.0。这里HUST指**河内理工大学**。实验设置参见[原始数据论文](https://doi.org/10.1186/s13104-023-06400-4)。使用者应保留作者、版本、来源、[许可链接](https://creativecommons.org/licenses/by/4.0/)和处理说明，不暗示原作者认可本项目。

原始数据不随源码分发。包内`hust_manifest.json`固定48个官方文件的名称、地址、字节数和SHA256；下载总量325,137,779字节，约325 MB。首次下载需明确传入`--download`，随后可离线复现。损坏缓存会报错，不被当作有效数据加载。数据许可独立于代码MIT许可。

所选子集包含6205/6206/6207/6208四种轴承，0/200/400 W三个负载，健康、内圈、外圈、滚动体四种单一状态。组合故障和6204未纳入，不能据此声称支持开放集或组合故障。

## 先划分原始记录，再取窗口

| 部分 | 轴承型号 | 原始记录 | 窗口 |
|---|---|---:|---:|
| 训练 | 6205、6206 | 24 | 768 |
| 验证 | 6207 | 12 | 384 |
| 测试 | 6208 | 12 | 384 |

同一型号的全部负载和类别留在同一部分。每条记录均匀取32个不重叠4096点窗口；一条记录的窗口不能跨部分。型号分组比随机窗口划分更严格，但仍不证明实际物理轴承身份已被完整识别，12条测试记录也不等于12个独立设备。

按原论文采用51,200 Hz采样率。MAT变量`fs`实际是轴转频率，例如24.93 Hz，**不能作为采样频率**。加载器只读取`data`。

实查有5条信号少于论文描述的10秒：B602、B604、B800、B802、B804。程序按文件实际长度取窗，记录真实样本数和时长，不补齐成10秒；最短B804为209,000点，约4.082秒。

原始幅值单位和采集时间未核实。每窗去均值、除以本窗RMS，处理后单位为无量纲`1`。这会去除幅值信息，是当前简单基线的限制。该变换不需要跨样本学习；特征均值、标准差、类别中心均只用训练部分估计。

## 分类与检索

分类器用55维固定特征：7个形状/频谱统计量、32段对数功率、16段包络功率。训练集标准化后，计算四个类别中心；用距离最近的中心分类，`softmax(-欧氏距离)`输出分数，温度固定1。它是简单参照，分数未经校准，不是诊断正确概率。

检索只使用768个训练窗口，按同一标准化特征的距离排序，最多取5条，每条原始记录最多保留一个窗口。查询不读取测试标签；测试文件名和真实标签不传入分类、检索查询或报告。真实标签只用于训练部分拟合以及离线评测。

分类器和检索共享特征，因此会出现相关错误；多条记录也可能来自同一轴承，不能当作独立证据。

默认类别契约仍为`faults-v1`（0内圈、1外圈、2滚动体）。显式配置`Settings(label_schema="bearing-health-v1")`或`DIAG_EVIDENCE_LABEL_SCHEMA=bearing-health-v1`加入3健康。未知类别仍拒绝，不映射成健康。适配器、校验器和报告使用同一显式契约，普通样本元数据不能替换它。

## 首轮真实分类结果

所有模型参数和0.5/0.8阈值在查看结果前固定，没有用验证集或测试集调优。验证部分也报告结果，防止只展示较好的测试型号。

| 指标 | 验证6207 | 测试6208 |
|---|---:|---:|
| 窗口准确率 / 平衡准确率 | 16.67% | 67.19% |
| 记录多数投票准确率 | 25.00% | 75.00% |
| 健康样本误报率 | 98.96% | 100.00% |

测试四类召回率分别为内圈95.83%、外圈100%、滚动体72.92%、健康0%。这些是本子集的实测结果，不代表通用能力。窗口之间相关，不以384个窗口计算独立样本置信区间。

| 测试输出方式 | 覆盖率 | 已输出结论错误率 |
|---|---:|---:|
| 分类器直接输出 | 100.00%（384） | 32.81%（126） |
| 仅格式校验 | 100.00%（384） | 32.81%（126） |
| 置信度≥0.5 | 88.80%（341） | 29.62%（101） |
| 置信度≥0.8 | 2.86%（11） | 18.18%（2） |

提高阈值会大幅降低覆盖率；不能把11个输出的错误率当作整体精度显著改善。真实数据结果表明，**当前首要问题是健康误报与跨型号泛化**，添加健康类别只解决表示问题，没有自动解决识别问题。

## 真实时间缺失与人工回放分开

原始记录没有已核实的采集/可用时间，原生场景如实缺失。启用严格参考检查后，没有历史参考能通过时间条件，结论均限制为weak，覆盖率为0。此时已输出结论错误率为`null`（无定义），不是0%。这说明获取元信息和设计拒绝策略都有实际成本，不能据此声称准确率提高。

另一组明确标记为**人工虚拟时钟**，将训练参考放在2000-01-01、决策截止放在2000-01-02；这些日期不是真实采集时间。在固定真实分类和检索输出上，分别注入单位、采样率、预处理、可用时间或角色错误。两种规则接收逐项相同的工具输出。

| 测试场景 | 原规则保留的中等及以上结论 | 严格检查后 |
|---|---:|---:|
| 原生缺少时间 | 341 | 0 |
| 人工兼容参考 | 341 | 341 |
| 所有参考单位/采样率/预处理不符，各一个场景 | 各341 | 各0 |
| 全部未来才可用/缺少可用时间/角色不符，各一个场景 | 各341 | 各0 |
| 5条中1条不兼容 | 341 | 341，仅4条计入支持 |

兼容场景的新误拒绝为0，但输出错误率仍为29.62%，与0.5阈值相同。这里证明的是字段规则能执行，**没有证明其在相同覆盖率下降低真实分类错误率**。每个策略还报告相同输出数量下的置信度排序对照，排序不使用真实标签。

人工兼容场景中，验证集high支持的118个输出有76个分类错误；测试集high支持的26个输出有1个错误。`high`不能解释为分类可靠概率，分类与检索一致也可能共同出错。

## 运行和产物

在源码目录执行（输出目录必须尚不存在）：

```bash
python -m pip install '.[benchmark]'
python -m diag_evidence benchmark-hust \
  --cache-dir artifacts/hust-data \
  --output-dir artifacts/hust-run-1 --download
```

保留缓存后，改用新输出目录并省略`--download`即可离线复现。基础安装和普通测试不依赖SciPy；真实MAT读取需要`[benchmark]`扩展。

主要产物：`dataset_manifest.json`（来源和许可）、`split_manifest.json`（原始记录分组和窗口）、`model.json`（训练统计和中心）、`frozen_tools.jsonl`（真实工具输出）、`predictions.jsonl`（分场景结果）、`metrics.json`（所有指标、对照与环境）、`full_workflow_smoke.json`（8次完整工作流调用）和SHA256清单。冻结输出不含原始波形。

完整工作流使用内存transport实时运行所训练的模型和检索库，每类一个测试查询，各比较两种规则。这不是已部署HTTP分类服务；HTTP处理由独立本机集成测试验证。毫秒指标是本机计算成本，未含网络、磁盘、模型服务部署或LLM开销。

## 后续研究顺序

1. 先诊断健康误报：逐记录检查特征分布、传感器/型号差异与训练覆盖；增加独立健康记录，采用按记录/设备分组的验证。已查看过的6208结果不能继续冒充未见测试集。
2. 在训练/验证部分比较原始幅值与无量纲形状特征、简单线性模型与树模型；增加轴频归一化或包络特征的对照。所有选择固定后，再用新留出型号或另一数据源评测。
3. 增加可校准的拒绝/分布外检测，报告健康误报、故障漏检、风险—覆盖率和相同覆盖率对照；健康类别与未知状态分开。
4. 用独立来源或不同信息模态支持结论，研究分类与检索相关错误。严格参考检查只解决声明适用性，不能代替模型验证。
5. 再讨论多主体信息时效与冲突；TimesFM仍作为独立数值预测实验验证，当前没有完成真实推理回测。
