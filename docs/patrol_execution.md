# 巡检任务执行确认

`patrol-demo --execution confirmed` 为每次派工分配编号。机器人接单后，调度器为该任务保留派工权，直到收到完工确认、故障中断、取消或查询超时。机器人做完后可以执行其他任务，已做的任务继续等待回执。

- 机器人按派工编号记录执行状态。同编号的重复指令返回接单确认，执行状态继续沿用。
- 预计完工加 4 步仍没有回执时，调度器发起状态查询。查询用 1 步到达机器人，查询回执与主动完工回执使用同样的报告延迟。查询可取回机器人缓存的完工结果。
- 查询 16 步后仍未获答复时，调度器关闭旧派工，并按剩余时限与能量重新评估。迟到回执按原编号处理。机器人故障会立即中断它正在执行的派工。
- 调度器收到对应的完工结果才确认完成。一次执行完成后，新的复检需求可以建成新的任务。仿真中的接单确认和停止均同步完成，执行结果缓存存活于本次仿真。

```bash
diag-evidence patrol-demo --scenario delayed --seed 7 --drop-completion-reports --output-dir artifacts/legacy
diag-evidence patrol-demo --scenario delayed --seed 7 --execution confirmed --drop-completion-reports --output-dir artifacts/confirmed
python scripts/patrol_execution_compare.py --output-dir artifacts/execution-study
```

用浏览器打开命令返回的 `replay_path`。执行确认模式可查看派工编号、等待确认、查询和超时事件。

对照使用布局种子 40–59、核验策略和匹配分配器。每种场景的两种模式使用相同输入，共 100 组配对、200 次运行。两列指标依次为原模式和执行确认模式。

| 场景 | 按时完成率 | 平均复检次数 | 平均能耗 |
|---|---:|---:|---:|
| 正常 | 97.50% → 97.50% | 0 → 0 | 141.00 → 141.00 |
| 回执延迟 12 步 | 100.00% → 97.50% | 32.55 → 0 | 216.65 → 141.00 |
| 主动回执丢失，查询回执延迟 12 步 | 81.88% → 97.50% | 78.05 → 0 | 290.30 → 141.00 |
| 机器人临时故障 | 98.75% → 98.75% | 0 → 0 | 137.90 → 137.90 |
| 回执延迟 32 步 | 91.88% → 99.38% | 62.00 → 9.35 | 273.65 → 249.60 |

延迟 12 步时，种子 42 和 48 出现机器人反复避让，各有两个任务未能按时完成。延迟 32 步超过默认查询等待时间，执行确认模式平均重派 9.5 次，仿真结束时平均有 7.95 个已实际完成的任务仍缺少确认。结果反映出固定超时、交通拥堵与任务时限的取舍。
